# معاينة مصنع الملابس عبر Supabase Edge Functions

## حالة النشر

- المشروع: `yumeijsyiphzdsulsubf` (قاعدة AMMCO المشتركة).
- Edge Function مستقلة: `garments-demo-preview`.
- النشر: `ACTIVE` بحسب Supabase Management API.
- يقدّم نسخة ثابتة من واجهة التطبيق والموديولات من GitHub `main` وقت إنشاء إصدار الدالة.
- **لا يوجد نشر تلقائي عبر push:** للحصول على تغييرات GitHub التالية في المعاينة يجب نشر إصدار جديد من الدالة.

### دخول المعاينة

الواجهة ليست مفتوحة دون قيد: يرسل المالك رابط دعوة خاصًا يحوي رمز وصول طويل. تتحقق الدالة من الرمز ثم تحفظ جلسة الدخول في **كوكي آمنة HttpOnly** لمدة 24 ساعة، وتعيد توجيه المتصفح إلى العنوان النظيف للمعاينة. لا يُخزّن الرمز في GitHub ولا يُضمّن في ملفات الواجهة.

**لا تنشر الرابط الكامل علنًا.** أي شخص يحصل عليه يمكنه فتح الواجهة في متصفحه، لكن بيانات التطبيق التشغيلية تبقى في تخزين متصفحه، وليست قاعدة البيانات المشتركة.

## بيانات التطبيق

- تشغيل المخزون والأوامر والجودة ما زال في `localStorage` لهذا النموذج.
- يمكن لحساب مصادق مسبقًا عبر Supabase رفع نسخة احتياطية/استعادتها يدويًا من جدول `public.garment_cloud_snapshots`، مع RLS لعزل المستخدم.
- لا توفر المعاينة تزامنًا متعدد المستخدمين، ولا مخزونًا مركزيًا، ولا نظام صلاحيات للمصنع، ولا دفترًا محاسبيًا متصلًا بالخادم.
- ملفات التطبيق التي نُشرت: `index.html` و`styles.css` و`app.js` و`src/factory-ops.mjs` و`src/cloud-backup.mjs`.
- لم يُعدّل نشر المعاينة بيانات AMMCO ولا وظائفه الحالية.

## استكمال التطوير

تطوير قاعدة معاملات منفصلة ومعتمدة لمخزون مصنع الملابس قبل أي تشغيل حقيقي. ينبغي تصميم مراجع المؤسسات، المستودعات، متغيرات الموديل، قوائم المكونات، أوامر القص، مراحل التشغيل، مخزون تحت التشغيل، الجودة، أوامر البيع والتكلفة وربطها بمعاملات PostgreSQL ذرية قابلة للمراجعة.

## GitHub Pages كبديل

يمكن تشغيل `Deploy Garments Preview to GitHub Pages` يدويًا بعد تفعيل **Settings → Pages → Source: GitHub Actions**. فشل التفعيل الأولي التلقائي لأن GitHub Actions token لم يكن يملك صلاحية إنشاء GitHub Pages site؛ تم تغيير الحدث إلى `workflow_dispatch` لتجنب إخفاقات نشر متكررة إلى حين التفعيل.
